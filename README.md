# Практична робота №1 — Notification / Alert Banner

## Обраний варіант
Варіант №5: інтерактивне сповіщення (Notification / Alert Banner).

## Мета
Створити адаптивний UI-компонент у стилі Figma, реалізувати його семантичними засобами HTML5/CSS3 та перевірити базові вимоги доступності.

## Структура
- `index.html` — семантична структура компонента.
- `styles.css` — дизайн-токени, адаптивність, hover і focus-visible.
- `script.js` — робота кнопок дії, закриття та повторного показу.

## Дизайн-токени
| Токен | Значення |
|---|---|
| Background | `#F4F7FB` |
| Surface | `#FFFFFF` |
| Text | `#172033` |
| Accent | `#2563EB` |
| Title | Inter / system-ui, 20 px, Bold |
| Body | Inter / system-ui, 16 px, Regular |

## Стани компонента
1. Default — звичайний вигляд сповіщення.
2. Hover — наведення курсора: рамка та тінь стають виразнішими.
3. Focus — клавіатурний фокус: помітна помаранчева обводка.
4. Dismissed — після натискання кнопки закриття сповіщення ховається, з'являється кнопка повторного показу.

## Як запустити
Відкрийте `index.html` у браузері. Додаткові бібліотеки не потрібні.

## Перевірка доступності
- Усі інтерактивні елементи — справжні `button type="button"`.
- Іконкова кнопка має `aria-label="Закрити сповіщення"`.
- Інформаційне повідомлення має `aria-live="polite"` для озвучення оновлення.
- Фокус клавіатури оформлений через `:focus-visible`.
- Передбачено `prefers-reduced-motion`.
- Контент адаптується до вузького екрана.

## Контрастність
Орієнтовні значення за формулою WCAG:
- `#172033` на `#FFFFFF` — приблизно 16.4:1.
- `#2563EB` на `#FFFFFF` — приблизно 5.17:1.
- `#172033` на `#EFF6FF` — приблизно 15.0:1.
Усі наведені пари перевищують вимогу 4.5:1 для звичайного тексту.

## Figma — як відтворити макет
1. Створіть новий Figma-файл і сторінку `PR1 — Notification`.
2. Створіть Frame шириною 1440 px, назвіть `Desktop`.
3. Додайте вертикальний Auto Layout: padding 64 px, gap 24 px, фон `#F4F7FB`.
4. Додайте заголовок `Інтерактивне сповіщення`.
5. Створіть картку сповіщення шириною приблизно 640 px, Auto Layout Horizontal, padding 20 px, gap 16 px, radius 16 px, фон `#EFF6FF`, обведення `#BFDBFE`.
6. Усередині картки розмістіть іконку Info 40×40 px, блок із заголовком і описом та іконкову кнопку закриття.
7. У текстовому блоці використайте вертикальний Auto Layout із gap 8 px. Заголовок — 20 px Bold, опис — 16 px Regular.
8. Створіть синю кнопку `Переглянути`: висота 44 px, горизонтальні відступи 17 px, radius 10 px, колір `#2563EB`, текст білий.
9. Перетворіть картку на Component. Створіть Component Variants з властивістю `State`: `Default` і `Hover`. У Hover змініть обведення на `#2563EB` та додайте легку тінь.
10. Створіть окремий Frame `Mobile` шириною 375 px. У картки встановіть Fill container, щоб вона стискалася за шириною.
11. Перевірте відступи та вирівнювання: усі елементи картки мають бути вкладені в Auto Layout, без ручного позиціювання.

## План ручного тестування
1. Відкрити сторінку у браузері.
2. Натискати Tab: фокус має послідовно перейти на «Переглянути», «Закрити сповіщення».
3. Натиснути Enter на кнопці «Переглянути»: має з'явитися повідомлення про виконану дію.
4. Перейти до кнопки закриття та натиснути Enter: картка зникає, фокус переходить на кнопку повторного показу.
5. Натиснути Enter на кнопці повторного показу: картка повертається, фокус переходить на кнопку закриття.
6. Змінити ширину вікна браузера та перевірити мобільне компонування.

## W3C Validator
Перед здачею вставте вміст `index.html` у https://validator.w3.org/nu/#textarea і натисніть Check. У разі повідомлень про помилки виправте їх. Не вказуйте у звіті, що перевірка пройдена, доки фактично не виконаєте її.
